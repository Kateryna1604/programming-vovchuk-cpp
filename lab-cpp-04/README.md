## Хід роботи

У цій лабораторній роботі було реалізовано ієрархію класів для роботи з поштовими повідомленнями.

**Базовий клас Mail було зроблено абстрактним. У ньому зберігається основна інформація про повідомлення:**

статус чернетки;
тема повідомлення;
текст повідомлення;
дані відправника;
дані отримувача;
кодування повідомлення.

**Для базового класу були реалізовані абстрактні методи:**

формування повідомлення;
обчислення розміру повідомлення.

Також були створені два класи-спадкоємці.

**SecretMail**

Цей клас представляє секретне повідомлення. У ньому перевизначено метод формування повідомлення. Під час формування всі цифри замінюються символом *, а розділові знаки видаляються.

**CompressedMail**

Цей клас представляє стиснуте повідомлення. Додатково містить поле ступеня стиснення. Розмір повідомлення обчислюється з урахуванням коефіцієнта стиснення.

Для роботи з колекцією повідомлень було реалізовано клас MailList, який зберігає масив вказівників на базовий клас Mail. Це дозволяє працювати з об'єктами різних типів через один список.

Також були реалізовані методи:

пошуку повідомлень певного користувача;
пошуку всіх секретних повідомлень;
підрахунку загального розміру всіх повідомлень.


**UML-діаграма**

У роботі була створена UML-діаграма ієрархії класів.

Файл діаграми:

doc/assets/uml.png

Діаграма демонструє зв’язки спадкування між класами:

Mail
├── SecretMail
└── CompressedMail

та використання базового класу в колекції MailList.
